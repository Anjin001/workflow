# Homework 2 要求对应

依据课程作业二第 2 至 4 页。本文区分课程必做要求、课程推荐项与本项目自行限定的实现范围。

## 必做项

| 课程要求 | 项目实现 | 验证方法 |
|---|---|---|
| 至少 2 个 Agent 协作完成完整流程 | CodingAgent、ReviewAgent、FixAgent 三个角色 | 真实模式使用独立角色提示词；离线模式可复现全部调用 |
| Agent 间消息传递或状态共享 | WorkflowState 与结构化输入输出 | 查看 task、review、validation 的流转与步骤快照 |
| 基本流程控制，顺序执行 | 编码、验证、审查、修复、重新验证 | 查看 runner 和 events.jsonl |
| 可运行 MVP，无需复杂调度 | 双击进入网页，另保留 CLI、依赖清单、任务示例 | 按 README 从启动到运行复现 |

课程代码审查方向明确列出“编码 → 审查 → 修复”。本项目增加验收工具提供证据，保留这三个角色的协作关系。

## 推荐项

| 推荐项 | 状态 |
|---|---|
| 条件分支、循环、并行等高级控制 | 已实现条件分支和有限修复循环；未加入并行 |
| 可视化 Workflow 编排界面，可选 | 已有拖动节点、手动连线、自定义角色、结构校验和按图执行；支持流程快照与节点输出 |
| 执行日志与状态追踪 | run.log、events.jsonl、snapshots、版本源码 |
| 错误处理与恢复机制 | 请求重试、格式恢复、超时、失败状态；无断点自动续跑 |
| 复用作业一 Agent 或参考经验重设计 | 参考原有模型调用、角色提示和工具验证的分层方式重设计 |

## 评分关注与证据

- 流程完整性 40%：提供直接通过、修复后通过、达到上限三种路径。
- Agent 协作 30%：各角色都保留原始需求；审查和修复共享当前版本及实际证据。
- 可扩展性 20%：模型接口、Agent、验证工具、持久化与流程控制分离。
- 文档 10%：README 说明使用，Design 说明架构、状态和扩展，本文对应课程要求。

## 项目范围与验证说明

单文件 Python 函数、JSON 验收契约和模型 JSON 输出是本项目的设计选择，不是课程强制技术栈。

离线固定模型和 HTTP 模拟请求只能证明流程与适配代码的行为。实际模型服务需要配置有效密钥后运行，提交前应保留自己的真实运行记录，不能将离线结果标为真实模型效果。
