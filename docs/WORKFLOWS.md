# 可视化工作流与问题验证

## 使用

双击 start.bat，在左侧进入「工作流设计」，或点击任务输入框上方的当前流程名称。

1. 从三角色默认流程或四角色交叉验证模板开始。
2. 选择节点后添加自定义角色，会插入该节点的后续路径；选择连线后添加，会插入那条连线。
3. 配置角色名称、职责提示词及需要读取的信息，点击「应用节点设置」。上游输出必选，其他信息可勾选。
4. 拖动卡片顶部调整位置；点击起点出口再点击终点入口即可连线，也可使用设置区的起点、出口、终点表单。连接同一出口会替换旧连线。
5. 点击「检查结构」，再「保存并使用」。载入流程列表包含内置模板和本机保存的流程。可以导入、导出 JSON；撤销保留最近 30 次画布操作。
6. 返回任务、确认验收并运行。结果中的「流程图」展示实际走过的节点及每个节点的执行轮次，点击节点查看信息来源、版本和输出。「问题验证」展示逐条判定与源码证据。

缩放可选择适应画布或指定比例，画布支持滚动。图上位置仅影响显示，连线决定实际执行顺序。

本机保存的流程位于 workflows/，不提交 Git 或作业包。当前选择记在浏览器中。每次运行另外保存 workflow.json；执行器持有独立副本，运行中编辑或保存画布不影响正在进行的任务。下载结果包包含该流程快照。

## 第一版支持的图结构

主路径：开始 → 编码 → 执行验收 → 发现问题 → 可选验证者 → 结果判定。

判定有两个出口：通过路径最终到完成，修复路径经过修复节点后回到执行验收。自定义角色可以插在以上路径的连线上。它们负责分析与建议，不能直接改变源码、验收用例、其他角色的结论或运行规则。编码、审查、修复与验证者可填写补充关注点，原有角色契约仍生效。

这不是任意图执行系统：第一版不支持任意循环、并行、多个写代码节点、多个发现者或自定义工具。核心节点各一个，验证者最多一个，自定义节点可以多个，总节点不超过 24 个。核心步骤的顺序约束用于保证代码版本、验收、审查之间一致。

结构编译会拒绝孤立节点、不存在的端点、重复出口、绕过核心步骤、无约束循环和读取尚未产生的数据。修复后旧验收、审查和问题验证立即失效；修复后的自定义节点不能再读取它们。每次流程还受任务修复上限（0–10 次）和总步数上限（10–300 步）约束。上限到达时保存记录并停止，不标为成功。

自定义角色通过 JsonAgent 调用当前配置的模型，输入由勾选的信息与直接上游输出组成；输出固定为 summary 和 recommendations。上游输出附带当前版本的分析建议，所以建议能经过验收工具传递给下游 Agent。修复后清除旧版本分析，只保留编码前产生的任务级建议。角色不接触 API Key。节点记录中的输入保存字段名、版本与上游标识，源码正文通过 versions/ 中的版本文件追溯，避免反复复制大段源码。

## 验证者

默认三角色流程保持课程基础范围。点击「＋ 问题验证者」或使用四角色模板，即启用交叉验证扩展。

发现者先输出候选问题；验证者读取原始需求、当前源码、真实验收结果与编号候选，逐条输出 confirmed（已确认）、rejected（已驳回）或 uncertain（待确认）。每条候选必须出现一次，不能无声遗漏。结论绑定当前代码版本与源码哈希。

程序检查源码引用确实存在，确认结论引用的片段还必须覆盖候选标注的行号；驳回结论可以引用其他位置的保护逻辑。缺少或伪造引用、确认定位不一致时，结论降为待确认。引用存在只是定位证据，不代表语义必然正确；验证者仍可能误判。只有确认的问题交给修复者，但验收失败独立要求修复，不能被验证者覆盖。只有待确认问题时状态为 needs_review，需要用户检查证据；不提供一键绕过验收的自动批准。

没有候选问题时不额外调用验证模型。离线模式里的自定义角色返回明确标注的占位分析，验证者返回固定演示判断；它们用于检查调度和展示，不代表真实提示词执行或误报改善。真实效果需要在同一批人工标注样例上对比启用/关闭验证者，记录误报、漏报、误驳回、耗时与 Token。

验收仍在本机子进程运行，不是安全沙箱。自定义角色暂时没有执行任意命令或修改项目文件的工具。

## 阅读源码

- workflow/graph.py：节点、边、结构编译与本机流程库。
- workflow/graph_runner.py：逐节点调度、共享状态、修复回路和结束判断。
- workflow/verification.py：候选编号、模型核实、证据检查与已确认问题筛选。
- web/assets/graph-ui.js：画布、拖动、连线、角色编辑及执行图。
- tests/test_graph.py、tests/test_verification.py：约束、真实验收、数据传递与错误路径。
